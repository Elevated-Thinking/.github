# .github

Public organization profile and shared contribution and security policies for Elevated Thinking repositories.

## Shared issue forms

Bug Report and Feature Request forms in `.github/ISSUE_TEMPLATE/` are the defaults for public and private repositories in this organization. They assign the native Bug or Feature issue type and corresponding label. Those labels must exist in every consuming repository.

Repositories inherit the whole default template folder only when they have no local issue templates or template configuration. A local `config.yml` alone also overrides these defaults. Keep the shared forms here instead of copying them between repositories.

Keep GitHub's built-in private vulnerability reporting option where available. Do not add a duplicate security contact link or a public security issue template. Security policies remain the source of reporting instructions.

Issues belong to repositories. Add accepted work to the organization-owned Elevated Thinking project and set Status, Priority, ownership and scheduling during triage. Templates capture the user's problem; maintainers refine acceptance criteria, split work into sub-issues and record dependencies. Native issue types are shared across the organization; custom project fields belong to the project where they are defined.

Maintainers can use a blank issue for internal tasks. Include a goal, acceptance checklist and dependencies, assign the Task type, and add it to the project. Users do not need internal phase, track or story identifiers to submit a request.
